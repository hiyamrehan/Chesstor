\chapter{System Design}
\section{System Architecture}
The system is layered (L0--L11 in the implementation specification). The core path is:
frame $\to$ quality gate $\to$ board localisation/tracking $\to$ rectification $\to$ 64-square extraction $\to$
per-square observation $\to$ temporal buffer $\to$ legal-hypothesis scoring $\to$ confirmation policy $\to$ trusted
state $\to$ FEN/history $\to$ Stockfish $\to$ overlay and logs. The proposal's four-tier architecture
(presentation, edge, cloud application, data/analytics) is retained, with the privacy rule that only FEN and moves,
never video, cross the device boundary.

\section{Interfaces and Dependencies}
The observer exposes \texttt{ObservationFrame(timestamp, probs[64$\times$3], visible[64], quality)}; the tracker
consumes frames and returns \texttt{Commit} objects. This boundary lets the recogniser be replaced (classical $\to$
CNN $\to$ detector) without touching the core. External dependencies are listed in Section~\ref{sec:deps}.

\subsection*{API between the app and the core}
The React app talks to the core through a small HTTP API (FastAPI). Raw frames are processed in memory and never stored.
\begin{longtable}{p{0.38\textwidth}p{0.5\textwidth}}
\toprule Endpoint & Purpose\\ \midrule
POST /api/sessions & start a live or simulated session (colour chosen by the player)\\
POST /api/sessions/\{id\}/calibrate & four tapped corners + frame; board orientation found by trying four rotations and checking the starting position\\
POST /api/sessions/\{id\}/frame & one camera frame $\to$ quality, occlusion mask, observation, tracker; returns the trusted state\\
POST /api/sessions/\{id\}/manual & user restores the board; new trusted anchor\\
DELETE /api/sessions/\{id\} & end session; returns the PGN of confirmed moves\\
POST /api/analyze/pgn & per-move engine review, accuracy, evaluation series\\
POST /api/analyze/video & not implemented (returns 501)\\
\bottomrule
\end{longtable}
The occlusion mask is tone-agnostic (border-ring colour deviation, no skin-colour model) so it does not fail on wooden boards or
bias across skin tones; its accuracy on real hands is untested.

\section{Architecture Decisions and Rationale}
\begin{itemize}
\item \textbf{Observation = occupancy + colour now:} the rules identify the piece, so a cheap, robust observation can be tested first; full 13-class recognition follows.
\item \textbf{Deterministic scoring, not a learned tracker:} explainable, testable, and enough for the first implementation; weights are tunable and frozen before evaluation.
\item \textbf{Trusted state mutates in one place:} everything else can wait, doubt or escalate.
\item \textbf{Guest mode by default:} live tracking and local history need no account.
\end{itemize}

\section{Design Evolution}
Since the proposal: (1) the tracker's unexplained-evidence gate became a graded margin penalty after stress tests
showed the hard gate rejected correct moves under persistent errors (Ch.~7); (2) a missed-ply (two-ply) hypothesis
was added for recovery; (3) the baselines B1--B3 were made explicit ablation switches in the same code path.

\section{Data Design}\label{sec:data}
\textbf{Why accounts?} Live tracking and analysis of a single game need no account. An account is justified only
to (a) keep game history and analytics across devices and (b) back up PGNs. We therefore provide \textbf{guest mode}
(on-device storage only) and \textbf{optional sign-in}.

\section{Process / Behavior Design}
The session state machine (IDLE, CALIBRATING, INITIALIZING, TRACKING, TRANSITION, CONFIRMING, UNCERTAIN,
LOST\_BOARD, MANUAL\_CORRECTION, ENDED) is implemented with an explicit allowed-transition table; illegal
transitions raise errors and are unit-tested. The confirmation policy: a change enters TRANSITION; when the
window is stable the decision is \emph{commit} (best hypothesis wins by margin), \emph{no move} (transient), or
\emph{unsure} (UNCERTAIN, re-evaluated each frame, escalating to MANUAL\_CORRECTION after a timeout).
